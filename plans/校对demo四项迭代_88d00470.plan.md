# 校对 Demo 四项迭代

基于现有代码（`app.py` + `proofreader/*` + `ui/*`）增量改造，不重写。

## 迭代 1：去掉列角色，改为单个"配对关键列"
列角色（关键列/源列/目标列/忽略）对同构表无意义，移除整套。按关键列配对改用单选下拉。

- `ui/app.js`：删除 `renderColumns()` 的四角色下拉；列角色 state 改为每个文件一个 `keyCol`（列号或空）。仅在配对方式=按关键列时，在该文件范围卡里显示"配对关键列"下拉（选项来自该范围的列表头）。按行号模式不显示任何列选择。
- `ui/index.html`：步骤2 配对方式说明微调。
- `proofreader/pairing.py`：`build_row_records(scope_cells, key_col_index=None)` 改为收录范围内全部非空单元（不再按 role 过滤），`key` 取自 `key_col_index` 那一列；删除对 `ROLE_*` 的依赖。
- `proofreader/excel_reader.py`：`detect_columns` 去掉 `suggested_role`，只返回 `{index, letter, header}`（供关键列下拉用）；移除 `ROLE_*` 常量或保留为空不再使用。
- `proofreader/prompt.py`：`_render_record` 去掉 `[role]` 前缀，改成 `coord(header)=value`；母本/目标行都展示各自全部单元。
- `proofreader/rules.py`：删掉"源列/目标列"相关措辞，五维度模型其余不变。
- `app.py` `_run_proofread`：payload 由 `columns` 改为 `key_col`；不再 `_coerce_columns`。

## 迭代 2：母本/目标多选（按"区域条目"）+ 保存配置
多选的单位是"区域条目（文件 + sheet + 范围）"，不是文件。因为母本内容可能分散在同一个文件的不同 sheet——所以**同一个文件可以被加多次，每条选不同 sheet/范围**；不同文件的区域也能混加。多个目标条目都对照"同一组母本条目池"（母本池化为共同依据），逐个目标跑校对。配置保存到本地会话，下次启动自动恢复。

- 数据模型（`ui/app.js`）：`S.baselines = []`、`S.targets = []`，每项是一个区域条目 `{id, path, name, sheets, sheet, range, keyCol, validated, ...}`；同一 `path` 可出现在多个条目里（各自 sheet 不同）。`S.relationship/S.pairing/S.dims/S.standard` 仍全局。
- 步骤1（`ui/index.html` + `app.js`）：母本、目标各是"条目列表 + 添加区域 + 删除"。"添加区域"先选文件（可复用已选过的文件，避免重复选盘），生成一条条目；同一文件再点一次"添加区域"即可加它的另一个 sheet。
- 步骤2：每个母本条目、每个目标条目各渲染一张范围卡（sheet 下拉 + 范围 + 预览 + 校验回显），多卡纵向排列。卡片标题体现"文件名 · sheet"以区分同文件的不同条目。
- 后端（`app.py`）：`run_proofread` 接收 `baselines:[条目...]`、`targets:[条目...]`。每个母本条目各自 `extract_cells` 后 `build_row_records`，按条目顺序**池化合并**成母本记录池（条目坐标里带 sheet 名，定位不混淆）。对每个目标条目：`pair(母本池, 目标记录, mode)` → 组装提示词（全范围上下文含全部母本条目范围 + 该目标范围）→ 调 LLM → `normalize_findings`。逐目标串行，合并所有 findings（`文件` 列区分到"文件·sheet"），返回合并结果 + 每条目计数。
- `proofreader/prompt.py`：`build_user_prompt` 的母本上下文改为接收母本条目列表，逐条渲染（标明文件名+sheet+范围）。
- 配对取舍：多母本条目下"按行号"按池化顺序对齐（plan 标注局限，推荐多母本时用关键列）。
- 保存/恢复（新增）：`app.py` 增 `save_session(state)` / `load_session()`，写本地 `session.json`（加入 `.gitignore`）；存条目清单（path/sheet/范围/keyCol）+ 关系/配对/维度/标准配置。前端加"保存配置"按钮；启动时 `load_session()` 恢复，文件缺失则标注让用户重选。

## 迭代 3：结果表限尺寸 + 保留滚动
- `ui/style.css`：`table.result` 用 `table-layout: fixed; width:100%`，给各列设 `width`/`max-width`；单元格 `overflow:hidden; text-overflow:ellipsis`（`依据`/`原文` 悬停 tooltip 看全文）。`.result-table-wrap` 保持 `max-height`（限高）并加 `max-width:100%` + `overflow:auto`（横竖双滚动）。预览网格同样限高限宽。

## 迭代 4：预览窗框选范围
把只读预览网格改成可框选，选中即回填范围框。

- `ui/app.js`：`renderPreview()` 给单元格绑定 `mousedown/mouseover/mouseup`，记录起止单元，高亮选区矩形。预览表头用绝对列字母、首列显示绝对行号，因此选区可直接换算成绝对 A1（如 `C7:F20`）。`mouseup` 时写入范围输入框并触发 `refreshScope()`（重渲染到新范围）。
- 行为：选 sheet 后默认预览"已用区域"（受 `max_preview_rows` 限制），在其中框选缩小范围；超出预览窗口的行先用范围框输入。局限在 plan 标注。
- `ui/style.css`：选区高亮样式 `.cell-sel`，单元格 `cursor:cell`，禁用文本选中。
