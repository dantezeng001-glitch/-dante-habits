# 移除内部术语库

只保留统一表述（中/英/法翻译对照，进润色软参考），彻底删掉内部术语库（glossary）。顺手把术语库从 `{ unified, glossary }` 扁平成 `UnifiedTerm[]`，与 `style-palette` 一致，去掉单字段包装。

## 类型与数据

- `lib/types.ts`：删除 `GlossaryTerm` 与 `TerminologyStore`，只留 `UnifiedTerm`。术语库类型直接用 `UnifiedTerm[]`。
- `data/terminology.json`：从 `{"unified":[],"glossary":[]}` 改为 `[]`。

## 数据层

- `lib/store.ts`：
  - `getTerminology(): Promise<UnifiedTerm[]>`，读时容错——若读到旧的对象结构(`{unified:[...]}`)则取其 `unified`，是数组则直接用，缺失返回 `[]`。
  - `validateTerminology(data)` 校验为数组并逐行规整成 `UnifiedTerm`，删掉 glossary 分支。
  - `saveTerminology(list: UnifiedTerm[])`。

## API

- `app/api/terminology/route.ts`：`GET` 返回数组；`PUT` 校验数组，成功返回 `{ ok, count }`。
- `app/api/terminology/import/route.ts`：删除 `parseGlossary` 与 `GlossaryTerm` 引用，只跑 `parseUnified`，返回 `{ unified, filename }`；422 文案改为"未识别到术语表:请确认表头含 ZH/EN/FR 列"。

## 组件

- `components/admin/TerminologyManager.tsx`：
  - 删掉子表切换(`SubTab`、`sub` 状态)、内部术语库整段表格与 `EMPTY_GLOSSARY`、glossary 相关 state/渲染。
  - 只保留统一表述单表 + 搜索 + 上传 xlsx + 保存。
  - 导入合并只追加 `unified`。
  - 顶部说明文字去掉"内部术语库仅供查询"那句，保留"统一表述(中/英/法)在翻译时作为术语对照软参考注入，只统一拼写表达，不强制改写"。

## 软参考

- `lib/prompt.ts`：`buildUserPrompt` 里 `termReferenceBlock(req.input, terminology)`（terminology 现在就是数组），`termReferenceBlock` 第二参数类型保持 `UnifiedTerm[]`，逻辑不变。

## 前台面板

- `app/page.tsx`：可展开「专有术语库」面板复用 `TerminologyManager`，无需改（内部已无 glossary）。

## 验证

- `npm test`（vitest）通过；`npm run build` TypeScript 通过、路由不变。
- 手测：上传 `Shokz统一表述知识库.xlsx` → 仅统一表述入库可保存;上传 `PMKT产品营销专业术语库.xlsx` → 因无 ZH/EN/FR 表头返回 422(符合预期,该文件已不再适用);中→英润色命中术语用标准译法、未命中不受影响。
