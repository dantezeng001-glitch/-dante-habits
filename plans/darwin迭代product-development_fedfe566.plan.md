# Darwin 迭代：product-development Skill

## 基线评估结果

总分 **63.7 / 100**，最弱 3 个维度：
- D4 检查点设计（2.8/7）-- 路径 A 全程无用户确认
- D3 边界条件（5.0/10）-- 无中间切入、无失败处理、无回退
- D5 指令具体性（9.0/15）-- 产出目录、输入组装规格模糊

## 优化计划：5 轮迭代，目标 85+

从 63.7 到 85+ 需要 +21.3 分，D6（资源整合 9 分）已到位，其余 6 个维度全部要拉升。按 Darwin 棘轮机制逐轮执行，每轮改完评分，涨则保留，不涨则回滚。

### Round 1: D4 检查点设计（4 → 9）

**改什么**：在 Pipeline 关键节点插入用户确认，防止自主失控。

- 路径 A：Step 2 / Step 4 / Step 5 产出后各插入一个确认节点，展示产出摘要、等用户说"继续"再往下走
- 路径 B：Step 4 产出后插入确认节点
- Step 0 入口路由增加**路径 C（中间切入）**：用户已有 PRD / 方案文档 / 技术文档时，识别产物类型直接跳到对应步骤
- 定义确认节点的标准格式（展示什么、用户可以说什么指令）

预估：D4 4→9（+3.5），D8 6→7（+2.5），总分 +6.0

### Round 2: D3 边界条件覆盖（5 → 8）

**改什么**：补充 5 类异常的处理方式。

- Subagent 失败/超时 → 重试一次，仍失败则报告原因 + 提供手动执行指引
- 用户想回退 → 识别"回到上一步""重做"指令，从前一步产出重新 dispatch
- 产出不满意 → 用户说"换个方向"时，调整 prompt 策略重新生成
- 路径 B 追问中途用户补充了录音 → 切换到路径 A，已收集的追问信息作为补充上下文
- 路径 C 产物格式不对 → 告诉用户需要什么格式，或尝试自动转换

预估：D3 5→8（+3.0），总分 +3.0

### Round 3: D5 指令具体性（6 → 9）

**改什么**：把三块模糊指令改具体。

**产出目录结构**：定义标准命名
```
{project}/
├── docs/
│   ├── 01-录音分析报告.md
│   ├── 02-产品方案.md
│   ├── 03-PRD.md
│   ├── 04-TECH_DESIGN.md
│   ├── 05-MOCK_SERVICES.md
│   └── 06-ACCEPTANCE.md
├── src/         ← Step 6 代码产出
└── DEMO_DATA/   ← 演示数据
```

**输入组装规格表**：每步 subagent 收到的 prompt 由哪些部分拼接，用表格明确列出（prompt 文件全文 + 哪些前序产出传完整 / 哪些只传摘要）。

**Step 6 任务拆分规则**：按 PRD 的功能模块逐个拆，每个任务指定角色 + 对应 PRD 章节 + 技术文档章节 + 交付文件路径。

预估：D5 6→9（+4.5），总分 +4.5

### Round 4: D2 工作流清晰度（7 → 9）

**改什么**：重新组织文档结构，让执行路径一目了然。

- 用编号系统统一全文：Step 0 / Step 1 / ... / Step 6 连续编号，路径 A/B/C 作为 Step 0 的子节点，不打断编号
- 每步的"输入 → 处理 → 产出 → 确认点"用统一的四行格式写，不靠散文描述
- "每步执行协议"从独立章节内联到每步里，避免读者跳来跳去
- "Subagent 调用协议"段落精简，角色清单保留，调用方式模板合入 Step 6

预估：D2 7→9（+3.0），总分 +3.0

### Round 5: D7 整体架构 + D1 Frontmatter 收尾（7→9 / 8→9）

**D7 改什么**：
- 文档顶部加一张总览流程图（Mermaid），一眼看清 Step 0 三条路径 → 汇入共同 Pipeline → 角色调度
- 精简重复描述（路径 A/B 的流程图和文字说明有重复信息）
- 角色选择规则从静态列表改为决策树格式

**D1 改什么**：
- description 末尾追加"支持中间切入：已有PRD直接生成技术文档"覆盖路径 C 触发场景

预估：D7 7→9（+3.0），D1 8→9（+0.8），总分 +3.8
