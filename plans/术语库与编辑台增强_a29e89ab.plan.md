# 术语库与编辑台增强

## A. 品牌事实瘦身（删除对文案零作用的字段）

删除 `positioning`、`products`、`proofPoints`、`compliance.superlativeNote`、`compliance.policy`。保留 `brand` / `toneCard` / `terminology` / `compliance.bannedPhrases` / `compliance.healthClaimNote`（这些是 `lib/prompt.ts` 真正注入的）。

- `lib/types.ts`：精简 `BrandFacts`，删掉 `positioning`、`products`、`proofPoints`、`BrandProduct`，`compliance` 收成 `{ bannedPhrases, healthClaimNote }`。
- `lib/store.ts`：`validateBrandFacts` 去掉对已删字段的校验；`getBrandFacts` 读旧文件时容忍多余字段。
- `data/brand-facts.json`：移除已删字段。
- `components/admin/BrandEditor.tsx`：删除 `EMPTY` 中对应键，删掉「定位 positioning」「产品 products」「信任背书 proofPoints」三个 Section 及 compliance 里的 superlativeNote/policy 两个 textarea。
- `lib/llm.ts`：`extractBrandFacts` 的 system 提示里结构清单同步去掉删除项。
- 先 Grep 全仓确认 `positioning`/`products`/`proofPoints` 无其它引用（`lib/guards.ts` 只按整 JSON 抓数字，不依赖具体字段，无需改）。

## B. 新增独立「专有术语」模块

数据分两类共存于一个文件（PMKT 仅查询、统一表述库可被软参考）：

- `lib/types.ts` 新增：
  - `UnifiedTerm { category, zh, en, fr, source? }`（统一表述库 + 产品名称表）
  - `GlossaryTerm { abbr, zhFull, enFull, explanation, scenario }`（PMKT 内部术语库）
  - `TerminologyStore { unified: UnifiedTerm[], glossary: GlossaryTerm[] }`
- `data/terminology.json`：新建，初始空结构。
- `lib/store.ts`：加 `getTerminology / saveTerminology / validateTerminology`（沿用原子写+备份）。
- `app/api/terminology/route.ts`：`GET`（公开读）/ `PUT`（口令写）。
- `app/api/terminology/import/route.ts`：`POST` 接收 xlsx，用 SheetJS 按表头确定列映射，把 `Shokz统一表述知识库.xlsx`（分类/ZH/EN/FR/来源 + 产品名称表）解析进 `unified`、`PMKT产品营销专业术语库.xlsx`（术语/中文全称/英文全称/解释/场景）解析进 `glossary`，返回结构化草稿供编辑核对。确定性解析，不走模型。
- `package.json`：新增依赖 `xlsx`(SheetJS)。
- `components/admin/TerminologyManager.tsx`：可复用组件——两张子表的增删改、关键词搜索过滤、xlsx 上传导入、保存（`authFetch`）。
- `app/admin/page.tsx`：`Tab` 增加 `"term"`，新增「专有术语」按钮与面板。
- `app/api/parse/route.ts`：补 xlsx 分支（flatten 成文本），让其它上传入口也兼容 xlsx。

## C. 前台可编辑入口

- `app/page.tsx`：在选项区加一个可展开「专有术语」面板，复用 `TerminologyManager`（紧凑模式），实现你要的"参考库前台可编辑"。

## D. 软参考接入润色（非绑定，任何语言方向）

- `lib/prompt.ts` `buildUserPrompt`：载入 terminology，用原文子串精确匹配 `unified` 的 `zh`（含产品名），把命中条目按目标语言取 `en`/`fr`/`zh` 组成「术语对照」注入，明确措辞为"仅统一这些术语的拼写/表达，其余请自由发挥，不要因此改写无关内容"。只注入命中的少量条目；`glossary` 永不注入。目标=原文同语言时也注入（解决英→英拼写问题）。

## E. 语言选项调整

- `components/LanguageSelector.tsx`：`SOURCE_LANGS`/`TARGET_LANGS` 加 `{ code: "fr", label: "Français" }`，删除 `ja`。
- `lib/prompt.ts` `LANG_LABELS`：加 `fr`，删 `ja`。

## F. 风格库每个风格支持上传解析

- `lib/llm.ts`：新增 `extractStyleFromDoc(docText)` → 返回 `{ name, essence, group }`（沿用反杜撰，只总结文档体现的风格特征）。
- `app/api/style-palette/extract/route.ts`：`POST { text }` → 调用上面函数返回草稿。
- `components/admin/StyleEditor.tsx`：每条风格行加一个 `FileDropzone`（inline），解析后回填该行 name/essence/group。（保存功能已存在，无需新增。）

## 验证

- `npm run build` 通过；`npm test`（vitest）通过。
- 手测：上传两个 xlsx → 专有术语正确分类入库并可保存；中→英润色时命中术语用标准译法、未命中不受影响；英→英能给出术语拼写参考且不改写其它；目标语言下拉出现法语、无日文；风格行上传文档能回填。
